# jev-A-share-trader 需求规格

状态：五轮需求讨论后确定，进入实现。本文区分用户确认的产品范围与实现中的技术细节。

## 1. 已确认的产品范围

- 项目名称：`jev-A-share-trader`。
- 面向 A 股，以技术分析为重点，以 Jev 参与决策。
- 同时支持个股深度分析、自选股批量分析和指定股票列表批量扫描；不再提供全市场扫描。
- 同时支持网页与命令行，共用行情、分析能力和结果。
- 技术分析采用第 6 节已确认的八类范围；具体公式、参数和形态识别规则在详细设计中明确。
- 暂时不做回测系统。
- 暂时不支持录入或管理实际持仓，保留未来扩展可能。
- 用户尚未要求交易执行；本次讨论聚焦分析与建议。

## 2. 已确认的结论形式

- 每只股票每次分析只给一个总判断：买入、持有或卖出。
- 系统自行确定该判断的适用周期，覆盖此前讨论的短线与波段场景。
- 不分别向用户输出两个相互独立的短线／波段主结论。
- 总判断必须列出支持与反对的技术证据。
- 数据不足、关键数据无效时显示“无法形成有效判断”，不能默认归入持有。
- 行情缺失和模型调用失败属于分析状态，不能伪装成有效的交易结论。

结论语义：

- 不依赖个人持仓的技术判断；持有对未持仓者表示观望，卖出对未持仓者表示回避。
- 系统从短线 2–5 个交易日、波段 5–20 个交易日中选择适用周期，对外只有一个主结论。
- 适用周期表示分析的时间尺度；卖出的适用周期是风险判断窗口，不表示等待该周期结束后再退出。
- 对外只提供总判断、适用周期及支持／反对证据，不提供入场、止损、失效或目标参考价位。
- K 线和指标值可用于查看分析依据，支撑阻力只作为内部分析及相对位置证据，不输出交易参考价位。

已确认的决策与解释方式：

- 采用方案 A：程序计算技术事实，Jev 分维判断，再由程序按明确规则汇总为一个总判断及适用周期。
- 汇总规则和权重应可检查、可配置；初始参数不宣称经过收益或胜率验证。
- 采用方案 A：结构化证据与中文模板组成解释，每条证据关联实际计算结果。
- 不另接生成式大模型撰写分析报告。
- 先生成及保留支持与反对证据，再按最终判断组织展示，避免只展示有利于结论的信号。

## 3. 已确认的数据边界

- 内置 AKShare（默认）和 Tushare Pro 两个可选数据提供方；Web 和 CLI 共用本机配置。
- 预留数据提供方扩展接口，未来可以接入其他行情来源。
- 用户自行配置其选择的数据提供方及所需凭据、权限；项目不提供行情数据服务。
- AKShare 常用公开行情接口不需要 API key，不应设置无意义的必填 key。
- 扩展提供方按需要声明 API key、token 等配置要求。
- 不将用户对 AKShare 的选择解释为已授权接入其其他账户或凭据。
- 本地获取与缓存是用户使用软件时的数据处理能力，不是项目运营方统一供应或分发数据。

## 4. 已确认的数据时点

- 仅根据最近已完成交易日的数据分析，不使用盘中未完成的当日 K 线。
- 在交易日 T 盘中运行时，最多使用 T−1 交易日及之前的数据。
- T 日收盘后，只有在所需 T 日数据已更新且通过完整性检查后，才能使用 T 日数据。
- T−1 指前一交易日，需要结合交易日历处理周末及节假日。
- 如果数据源尚未更新或字段未齐备，应显示实际截止日期和状态；不得把旧数据标为最新。
- “根据最新收盘价分析”按已完成日线 OHLCV 理解，仍使用该日开盘价、最高价、最低价、成交量和成交额计算技术指标。
- 周线、月线由同一截止时点的日线构造，仅展示和使用已完成周期。

## 5. 已采纳的数据工程要求

### 历史缓存与更新

- 首次建立所需历史行情库，后续增量更新。
- 网页和命令行共用行情库，不因重复分析而重复下载完整历史。
- 历史长度满足指标初始化需求；默认请求十年，至少260根完整日线，具体参数见计算口径。
- AKShare 个股日线上游采用东方财富优先、腾讯备用；大盘指数另支持新浪和腾讯。Tushare 独立获取行情、复权因子及参考指数，源切换时独立校验与缓存。

### 一致性

- 统一股票标识、字段、成交量／成交额单位、时间戳和复权口径。
- 必须处理复权，避免除权除息被误判为技术跳空或趋势变化。
- 切换备用来源前必须校验口径，不直接拼接不同来源、不同复权基准的价格序列。
- 复权历史发生变化时，需更新受影响的历史序列及指标，不能只追加最新一行。
- 区分停牌、休市、真实数据缺失及上市历史不足。

### 结果可追溯

- 每份分析显示数据截止时间、实际来源和数据缺失情况。
- 关键数据不足时停止形成有效交易判断，并给出具体原因。
- 批量扫描需报告成功、跳过、失败及待处理数量，不把部分完成显示为全部成功。

## 6. 已确认的技术分析体系

用户已确认以下八类覆盖范围。列出的指标及分析内容纳入第一版范围，具体参数和实现方式在详细设计中明确。

| 维度 | 分析内容 |
| --- | --- |
| 趋势 | SMA、EMA、WMA、HMA、KAMA、DMI/ADX、Aroon、SAR、Supertrend；均线排列与斜率 |
| 动量 | MACD、RSI、KDJ、Stochastic、CCI、Williams %R、ROC、MOM、TRIX、TSI |
| 量价 | 均量线、日量比、换手率、OBV、MFI、CMF、A/D、PVT、VWMA；放量／缩量与价量背离 |
| 波动 | ATR/NATR、布林带、Keltner 通道、Donchian 通道、历史波动率、带宽与挤压状态 |
| 价格结构 | 阶段高低点、支撑阻力、突破与回踩、缺口、趋势线、区间位置 |
| K 线及组合 | 实体／影线、十字星、锤头、吞没、早晚星、连续多根 K 线形态 |
| 多周期 | 日线主分析，结合周线／月线背景；识别周期共振及冲突 |
| 相对强弱 | 个股相对大盘和行业的表现、市场宽度、行业趋势 |

技术分析工程原则：

- 数值和可明确计算的事件由程序生成；Jev 评估信号组合及意义。
- 指标公式、参数和预热规则明确，跨来源保持一致。
- 相关指标按维度归组，避免将同类信号当作独立证据重复加权。
- 证据与真实指标值、发生日期和图上位置对应。
- 技术形态必须有可检查的规则；需要后续 K 线才能确认的形态不得提前标记为已确认。
- 日线估算不能冒充逐笔数据、真实订单流、盘口或真实筹码分布。
- Jev 输出的模型概率不称为实证交易胜率。
- 第一版不额外纳入缠论、艾略特波浪或筹码分布体系，后续可扩展。

## 7. 已确认的市场、扫描与结果界面

用户已选择市场范围 A、扫描模式 A，并确认不提供具体参考价位，界面支持中英双语且默认中文。

### 市场范围

- 覆盖沪、深、北交易所 A 股各板块，并允许用户选择扫描范围。
- 批量扫描默认排除 ST／*ST、退市整理、停牌及历史不足以满足必需指标的股票。
- 低流动性过滤按20日平均成交额设置，默认0表示不额外过滤，可由用户配置。
- 股票支持范围、默认扫描过滤及能否形成有效判断分别记录，不能混为一谈。

### 扫描模式

- 用户粘贴股票代码列表或使用自选股，每批最多 50 只；规范化代码、按输入顺序去重，拒绝空列表、无效格式与超限。自选股在创建时固定快照；未知股票单独记为失败。
- 逐只完成行情获取与分析，完成一只即保存并展示结果；进度按已处理数量计算。模型故障立即暂停；连续 3 只数据处理失败且仍有待处理项时自动暂停。
- 旧全市场任务仅保留查看及中止／删除，不再新建、恢复或重试。
- 对列表中全部通过基础过滤与数据校验的股票调用 Jev，产生完整的买入／持有／卖出分析，不采用技术条件预筛选。
- 支持进度、暂停／继续、失败重试、中止和结果缓存。新建入口、任务详情和扫描历史分离；入口按范围展示最近任务摘要，历史按范围和状态筛选。
- 暂停和中止在当前股票或准备步骤完成后停止后续处理。中止保留历史分析与缓存，任务详情保留已完成结果；新任务从批量扫描入口创建。
- 相同数据、模型、问题模板和汇总配置可以复用有效缓存；失败和部分完成应可见。

### 参考价位

- 支撑阻力属于内部技术分析范围。
- 不输出参考入场区间、失效价位、止损参考和目标区间。
- 不管理个人成本、仓位或收益目标。

### 界面与运行方式

- 提供中英双语界面，默认中文；语言切换覆盖界面、结论、证据、状态和导出。
- 侧栏固定为个股分析、批量扫描、分析记录、扫描历史；扫描任务和单次分析报告均为独立详情页，有稳定地址并支持刷新及前进／后退。
- 从扫描历史进入任务、从扫描任务或分析记录打开报告，逐级返回时分别保留各层范围、任务、筛选、页码和滚动位置。自选股默认打开最近报告，无报告时进入预填入口。
- 分析记录与扫描历史支持单条／本页勾选批量删除、确认及撤销上次删除。运行中的任务不可删除；删除任务保留分析报告，删除报告保留扫描中的原判断并移除报告链接。
- 打开报告只读取历史快照；按最新收盘发起新的分析不得覆盖原报告。有效缓存可复用原报告。
- 股票列表／筛选、总判断及适用周期、交互 K 线、指标副图、八维分析与支持／反对证据。
- 网页和命令行共用用户自己的行情缓存、配置及分析记录。
- 默认用户在本机运行，命令行与网页使用同一后端；支持 JSON、CSV、HTML 导出。
